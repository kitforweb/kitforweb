## What is a JWT?

A **JSON Web Token** is a compact string made of three Base64URL parts separated by dots: `header.payload.signature`. The header says which algorithm signed the token, the payload carries the *claims* (who the user is, when the token expires…) and the signature lets the server check that nobody tampered with it.

## How to use this JWT decoder

1. Paste the token on the left. A leading `Bearer ` is removed automatically, so you can copy the whole `Authorization` header from DevTools.
2. The header, payload and signature appear on the right, with the **expiry status** at the top: valid, expired, or not valid yet.
3. Time claims (`exp`, `iat`, `nbf`) are shown as dates in your language, with how long ago or how soon they happen.
4. To **verify the signature**, paste the secret (HS256…) or the public key (RS256, ES256…) under the token.

## Registered claims

| Claim | Meaning |
| --- | --- |
| `iss` | Issuer: who created the token |
| `sub` | Subject: usually the user ID |
| `aud` | Audience: who the token is for |
| `exp` | Expiration time (Unix seconds) |
| `nbf` | Not before: the token is invalid until this time |
| `iat` | Issued at |
| `jti` | Unique token ID, useful to revoke it |

## Why decoding is not the same as verifying

Anyone can decode a JWT, but only the right key can produce a valid signature. Your backend must **always verify** the signature and reject `alg: none` before trusting any claim. This tool refuses unsigned tokens when you ask it to verify them.
