## ¿Qué es un JWT?

Un **JSON Web Token** es una cadena compacta formada por tres partes en Base64URL separadas por puntos: `cabecera.payload.firma`. La cabecera indica qué algoritmo firmó el token, el payload lleva los *claims* (quién es el usuario, cuándo caduca el token…) y la firma permite al servidor comprobar que nadie lo ha manipulado.

## Cómo usar este decodificador de JWT

1. Pega el token a la izquierda. Si empieza por `Bearer ` se quita solo, así que puedes copiar la cabecera `Authorization` entera desde las DevTools.
2. A la derecha verás la cabecera, el payload y la firma, con el **estado de caducidad** arriba: válido, caducado o aún no válido.
3. Los claims de tiempo (`exp`, `iat`, `nbf`) se muestran como fechas en tu idioma, indicando hace cuánto o dentro de cuánto ocurren.
4. Para **verificar la firma**, pega el secreto (HS256…) o la clave pública (RS256, ES256…) debajo del token.

## Claims registrados

| Claim | Significado |
| --- | --- |
| `iss` | Emisor: quién creó el token |
| `sub` | Sujeto: normalmente el ID del usuario |
| `aud` | Audiencia: para quién es el token |
| `exp` | Fecha de caducidad (segundos Unix) |
| `nbf` | No antes de: el token no es válido hasta esa fecha |
| `iat` | Fecha de emisión |
| `jti` | ID único del token, útil para revocarlo |

## Decodificar no es lo mismo que verificar

Cualquiera puede decodificar un JWT, pero solo la clave correcta produce una firma válida. Tu backend debe **verificar siempre** la firma y rechazar `alg: none` antes de fiarse de ningún claim. Esta herramienta rechaza los tokens sin firma cuando le pides verificarlos.
